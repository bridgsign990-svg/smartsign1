# BridgeSign evaluation framework

This document defines the evaluation structure for the current project without claiming results that have not been collected.

## 1. Technical evaluation
Planned or to-be-conducted technical measures:

- static recognition accuracy for supported letters and sign classes
- macro F1 or balanced accuracy for multi-class performance
- confusion patterns and recurring misclassifications
- dynamic recognition readiness status, including dataset/architecture limitations
- model/data gap assessment for MSL, ASL, and experimental datasets
- deployment readiness checks such as inference loading, fallback behavior, and runtime stability

Status: evaluation to be conducted and reported explicitly when data are available.

## 2. Learning evaluation
Potential learning outcomes to measure in a guided study:

- pre-test score before lesson engagement
- post-test score after lesson completion
- score improvement across a lesson or module
- lesson completion rate
- assessment success rate
- learner confidence or comfort reading a sign or phrase

Status: evaluation design exists; no participant results should be claimed without actual testing.

## 3. Usability and accessibility evaluation
Potential usability measures:

- task completion rate for sign recognition or phrase use
- time to complete a learning task
- ease of learning score
- clarity of instruction and avatar demonstration
- communication success in a short user scenario
- accessibility feedback regarding device, audio, or visual support

Status: evaluation to be conducted with representative users when the study is ready.

## 4. Research reporting standard
The project should report the following explicitly:

- what is operational
- what is experimental
- what is future work
- what is not yet validated as MSL
- what is an engineering prototype instead of a classroom-ready system

## 5. Review-safe wording
BridgeSign should be described as:

> a modular assistive communication and sign-language learning prototype with static recognition support, avatar-based demonstrations, and experimental dynamic recognition infrastructure.

This wording is more defensible than claiming full MSL translation capability without validated local data.
